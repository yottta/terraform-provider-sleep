# Terraform provider that simulates long running actions

This is a simple and dumb provider that stores no information and calls no APIs.

The sole purpose of this is to test delays and how the provisioner system or the CI/CD behave in specific situations.

## Provider configuration

```hcl
terraform {
  required_providers {
    sleep = {
      source = "yottta/sleep"
    }
  }
}

provider "sleep" {
  max_default = 1
}
```

The only configuration this provider supports is the maximum amount of seconds a resource action can sleep (if not
specifically)
configured. If the `max_default` is not configured, then the provider will use the hardcoded default value (60 seconds).

## Resources

### `sleeper` managed resource

```hcl
resource "sleep_sleeper" "res1" {
  read_sleep    = 2
  plan_sleep    = 3
  apply_sleep   = 4
  update_sleep  = 5
  destroy_sleep = 6

  string = "string that will be stored in state"
  // OR (mutually exclusive)
  string_wo         = "value that will not be stored in the state"
  string_wo_version = 1
}
```

#### Arguments

* `read_sleep` - The number of seconds the provider should sleep before returning from Read. If not provided, the
  provider
  level configuration will be used to generate a random sleep time.
* `plan_sleep` - The number of seconds the provider should sleep before returning from ModifyPlan. If not provided, the
  provider
  level configuration will be used to generate a random sleep time.
* `apply_sleep` - The number of seconds the provider should sleep before returning from Create. If not provided, the
  provider
  level configuration will be used to generate a random sleep time.
* `update_sleep` - The number of seconds the provider should sleep before returning from Update. If not provided, the
  provider
  level configuration will be used to generate a random sleep time.
* `destroy_sleep` - The number of seconds the provider should sleep before returning from Delete. If not provided, the
  provider
  level configuration will be used to generate a random sleep time.

In order to be able to create dependencies between this resource type and other resource types, it also provides
3 arguments that can get different types of values:

* `string` - can be configured with a hardcoded string value or a value from a different resource type. This is a
  regular
  value meaning that will be stored in the state.
* `string_wo` - can be configured with a hardcoded string value or a value from a different resource type. This is a
  write-only attribute, meaning that will not be stored in the state and that it can be used to pass ephemeral values
  too.
* `string_wo_version` - the write only version associated with `string_wo`.

> [!NOTE]
> * For a specific resource instance, you can use `string` or `string_wo`, but not both. These are mutually exclusive.
> * When using `string_wo`, it is required to use `string_wo_version` too.

#### Attributes

* `id` - this will be generated during creation of the resource. Will not be stored by the provider, but reused later
  from the state.

### `sleeper` data source

```hcl
data "sleep_sleeper" "data" {
  id         = "random id"
  read_sleep = 3
  string_in  = "my custom information"
}
```

#### Arguments

* `id` - required identifier for the data source. This can be any random string value since this provider stores no
  information.
* `read_sleep` - The number of seconds the provider should sleep before returning from Read. If not provided, the
  provider
  level configuration will be used to generate a random sleep time.
* `string_in` - an optional field that will be used to be returned by the data source in the `string_out` attribute.

#### Attributes

* `string_out` - computed value that will be generated by the data source. It uses the information passed into
  `string_in` or if that is missing, it will use the value of the `id` attribute.

### `sleeper` ephemeral resource

```hcl
ephemeral "sleep_sleeper" "eph1" {
  id          = "random id"
  open_sleep  = 2
  renew_delay = "30s"
  renew_sleep = 1
  close_sleep = 3
  string_in   = "sensitive value"
}
```

#### Arguments

* `id` - required identifier for the ephemeral resource. This can be any random string value since this provider stores
  no information.
* `open_sleep` - The number of seconds the provider should sleep before returning from Open. If not provided, the
  provider
  level configuration will be used to generate a random sleep time.
* `renew_sleep` - The number of seconds the provider should sleep before returning from Renew. If not provided, the
  provider
  level configuration will be used to generate a random sleep time.
* `close_sleep` - The number of seconds the provider should sleep before returning from Close. If not provided, the
  provider
  level configuration will be used to generate a random sleep time.
* `renew_delay` - The number of seconds the provider will return back to the caller to instruct on when the `Renew`
  should be called. This is also used in the `Renew` response to schedule subsequent calls to `Renew`. If not provided,
  the renewal process will be disabled
* `string_in` - an optional sensitive field that will be used to be returned by the ephemeral resource in the
  `string_out` attribute.

#### Attributes

* `string_out` - computed sensitive value that will be generated by the ephemeral resource. It uses the information
  passed into `string_in` or if that is missing, it will use the value of the `id` attribute.
